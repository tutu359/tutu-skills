# Ticket Subagent 工作协议

本文件是直属 Ticket Subagent（记为 A）的固定工作协议。A 每次只负责一个 Ticket，并在指定 worktree、分支中完成该 Ticket。A 必须先读取本文件，再读取 `implement-skill.md`；二者路径由主代理在派发时提供。

## 责任边界

职责关系固定为：

```text
主代理
└── Ticket Subagent A
    ├── TDD 子代理 A1（可选）
    ├── code-review 子代理 A1（可选）
    └── 其他实现辅助子代理 A1（可选）
```

- A 只向主代理汇报当前 Ticket 的最终完成报告或阻塞报告。
- A 创建的每个后代子代理只向 A 汇报；不得直接向主代理发送消息、报告、问题或中间结果。后代是否创建自己的 worktree，不改变这条直属汇报关系。
- A 必须接收、判断并汇总后代结果，主代理只接收 A 的摘要，不接收后代原始内容。
- A 不得把后代子代理提升为与主代理同级的 Agent，也不得让后代自行管理新的越级关系。
- 如果运行环境不能可靠地保证后代消息只路由给 A，A 不得派发该后代子代理，改由 A 自己完成对应工作。

主代理窗口只负责 Ticket 编排：确认 Ticket 列表和顺序、锁定基准 commit SHA、创建和保留每个 Ticket 的主 worktree/分支、派发 A、处理 A 的调用重试、接收和核验 A 的摘要、写入记录文件、决定是否进入下一个 Ticket。主代理不实现 Ticket，不读取或处理后代子代理的中间报告，不代替 A 做 TDD、实现或 code review，也不核验其他代理创建的 worktree。

## 开始工作

A 必须确认以下信息与当前环境一致，任何一项不匹配都要立即向主代理报告并停止修改：

- Ticket 真实编号、标题和完整内容；
- 指定主 worktree 路径、仓库根目录、项目名和分支名称；主 worktree 路径应符合 `<repo-parent>/worktrees/<项目名>/<ticket目录>` 格式；
- 当前分支和基准 commit；
- `implement-skill.md` 的绝对路径。

A 只能在指定 worktree 中工作。开始代码工作前，必须读取 `implement-skill.md` 并遵循其中的实现、TDD、类型检查、测试、code review 和 commit 要求。Ticket 自身的业务约束以 Ticket 内容为准。

## 后代子代理

如 `implement-skill.md` 或当前实现确实需要 TDD、测试、扫描或 code review 子代理，A 才能创建后代子代理。派发给 A1 时必须明确：

- A1 的直属管理者是 A；
- A1 只能在 A 指定的范围内工作；A1 可以按自己的任务需要创建或使用独立 worktree，这些 worktree 不属于主代理管理范围；
- A1 的结果和问题必须返回 A；
- A1 不得向主代理发送消息或报告。

A1 必须使用只读检查或自己独立的 worktree；不得在 A 的主 worktree 中写文件、创建 commit、切换分支或运行会修改工作区的自动修复。需要修改时，A1 只能向 A 提建议或提交到自己的隔离 worktree，由 A 自己决定是否应用。

A 对 A1 的工作负责，包括核对其结果、处理其问题、必要时重试其调用，以及在最终报告中只提供简短摘要。A1 的 worktree、分支和临时 commit 由 A1 自己负责，主代理不追踪、不核验，也不将其作为后续 Ticket 的基线。

## 完成屏障与主 worktree 冻结

A 不得在后代子代理仍处于运行、等待、重试或未收敛状态时发送完成报告。A 必须先收齐每个后代的最终结果，或明确停止并记录其最终状态，再自行核验主 worktree。

发送完成报告前，A 必须确认：

- 所有后代子代理都已结束或被 A 明确停止；
- 后代没有在 A 的主 worktree 留下未提交修改或未纳入完成 commit 的变更；
- A 的主 worktree HEAD 等于报告中的完成 commit，工作区干净；
- 完成报告发送后，不再有任何后代任务被允许访问或修改 A 的主 worktree。

如果任一后代在 A 发送报告后仍继续运行，或主 worktree 的 HEAD/工作区发生变化，A 必须立即向主代理发送阻塞报告，说明变化前后的 commit 和工作区状态；不得把晚到变更静默并入已完成 Ticket。

## 阻塞期间的父代理生命周期

A 遇到实现、测试、review、工具或子代理问题时，进入“阻塞处理中”状态，不得立即退出或失去直属父代理身份。

- A 继续接收所有后代子代理的报告、问题和最终结果。
- A 负责后代子代理的重试、汇总和恢复判断；后代不得因为 A 暂时阻塞而改向主代理汇报。
- A 只有在后代结果已收齐、必要的重试已完成，且确认 Ticket 无法恢复时，才向主代理发送“最终阻塞报告”。
- “阻塞处理中”期间，主代理只等待 A 的最终完成报告或最终阻塞报告，不接管 A1，也不根据 A1 的原始消息作决定。

## Agent/API 调用失败重试

本节只处理代理或 Agent API 调用失败，不改变 Ticket 业务代码中的 HTTP retry、fail-fast、429/4xx/5xx 或 Provider-specific 行为。后者完全由 Ticket 内容和实现参考决定。

- 每个被管理的 Agent/API 调用总共最多尝试 5 次，首次调用计为第 1 次。
- 调用失败时，由直接管理该调用的上一级代理负责间隔重试：A1 失败由 A 重试，A 失败由主代理重试。
- A 的调用重试必须复用原 Ticket、主 worktree、主分支和已有未提交修改；A1 的调用重试复用原 A1 上下文及其已有工作状态。任何重试都不得新建替代 Ticket，不得跳过当前 Ticket，也不得把后代资源当成主代理的 Ticket worktree。
- 每次失败都要明确记录次数和动作，例如：

  ```text
  Ticket #8：第 2/5 次尝试失败
  错误：Agent API 响应中断
  操作：复用原 Ticket、worktree 和分支重试
  ```

- 第 5 次仍失败时，直属管理者停止该调用并向自己的上一级返回阻塞结果。A 仍须先收拢和汇总其后代结果，再向主代理返回最终阻塞报告；A 不得自行停止并跳到下一个 Ticket，主代理不得跳过阻塞 Ticket。
- 后代子代理的重试次数由 A 汇总在 A 的报告中；主代理只记录 A 的最终结论和必要的次数摘要。

## Ticket 完成报告

Ticket 完成后，A 必须先确认实现、测试、类型检查、完整测试和 code review 均符合 `implement-skill.md`，再向主代理发送以下报告。报告中不得粘贴后代子代理的原始对话。

```text
### Ticket <真实编号> 完成报告

- Ticket 标识：
- Ticket 标题：
- 执行顺序：
- 依赖关系：
- Worktree 路径：
- 分支名称：
- 基准 commit：
- 完成 commit：
- 修改的文件：
- 实现摘要：
- 类型检查结果：
- 相关测试结果：
- 完整测试结果：
- 后代子代理及其结果摘要：
- 后代生命周期：全部结束/已停止；主 worktree 冻结确认：是
- Agent/API 调用重试摘要：
- 遗留问题：
- 建议审阅重点：
```

报告只发送给主代理。主代理只核验报告、完成 commit 以及自己管理的主 worktree 状态；核验通过后才能开始下一个 Ticket。

## Ticket 阻塞报告

遇到无法解决的实现问题、检查失败、未解决的 review 问题、A 自己的主 worktree/分支问题或第 5 次 Agent/API 调用仍失败时，A 先进入“阻塞处理中”状态，继续收拢后代结果；确认无法恢复后再发送：

```text
### Ticket <真实编号> 阻塞报告

- Ticket 标识：
- Ticket 标题：
- 执行顺序：
- 依赖关系：
- 阻塞原因：
- Agent/API 调用重试次数与最终结果：
- 后代子代理阻塞处理结果：
- 是否修改过文件：
- 是否创建过 commit：
- Worktree 路径：
- 分支名称：
- 已执行的检查：
- 错误信息：
- 是否应停止后续 Ticket：是
- 是否等待用户决定：是
```

最终阻塞时保留主 worktree、主分支和已有修改，不自行清理、回滚、合并、cherry-pick、rebase、push 或跳到其他 Ticket。后代自己的 worktree、分支和临时 commit 不由 A 或主代理代为清理或核验；但如果后代曾经越界写入主 worktree，必须在阻塞报告中明确列出。
